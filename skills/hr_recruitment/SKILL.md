# HR 招聘安全数据 Skill

## 适用场景

当用户要求 Claude Code CLI / Agent 完成 HR 招聘相关任务时使用本 Skill，包括：

- 候选人筛选与推荐
- 人才库自然语言问答
- 招聘数据分析
- 招聘报告生成
- 保存 Agent 已生成的筛选推荐结果

本 Skill 是 HR 业务推理与执行层。HR MCP/API 后端只是安全数据服务层，只提供候选人安全画像、召回、事实查询和结果保存能力。

## 边界原则

- 你负责理解用户意图、读取岗位 Markdown 标准、推理、推荐、回答问题、分析和写报告。
- 后端 MCP/API 不负责推荐、问答、分析或报告生成。
- 不要要求后端读取岗位标准；标准由本 Skill 直接读取项目内 Markdown。
- 不要要求后端生成分析结论或报告。
- 不要让 Agent 生成自由 SQL。
- 不要请求或输出联系方式，除非用户明确具备高权限访问理由，且 MCP 后端字段策略允许。

## 可用后端 MCP 工具

仅使用以下 4 个后端数据工具：

1. `search_candidate_safe_profiles`
   - 用途：按岗位、状态、工作年限、技能关键词等受控 filter 召回候选人安全画像。
   - 注意：返回内容已经过字段权限控制。

2. `get_candidate_safe_detail_batch`
   - 用途：按候选人 ID 批量读取安全详情。
   - 注意：每批最多 50 人。

3. `query_talent_pool_facts`
   - 用途：返回 count、岗位分布、状态分布、来源分布等事实数据。
   - 注意：只把它当事实数据，不把它当结论。

4. `save_screening_result`
   - 用途：保存你已经生成的推荐结果。
   - 保存字段：`task_id`、`standard_ref`、`candidate_id`、`recommend_reason`、`risk_points`。

## 岗位标准映射

当前只支持以下六类岗位。其他岗位标准尚未补充时，应明确告诉用户“当前 Skill 尚无该岗位筛选标准”，不要硬套标准。

### `standard_markdown/xiaoman.md`

适用岗位：

- 后端工程师
  - 数据库岗位名：数字后端设计工程师
  - 可识别别名：后端工程师、数字后端、数字后端设计、后端设计工程师

- SOC设计工程师
  - 可识别别名：SOC设计、SoC设计、SOC设计工程师

- 原型验证工程师
  - 可识别别名：原型验证、FPGA原型验证、验证工程师

### `standard_markdown/yihai.md`

适用岗位：

- 芯片建模工程师
  - 数据库岗位名：CPU性能建模工程师
  - 可识别别名：芯片建模、CPU性能建模、性能建模、建模工程师

- 应用软件开发工程师
  - 可识别别名：应用软件、应用开发、软件开发、C++开发、系统软件

- AI芯片工程师
  - 数据库岗位名：AI芯片开发工程师
  - 可识别别名：AI芯片、AI芯片开发、AI芯片工程师

## 候选人筛选与推荐流程

1. 识别用户要筛选的岗位。
2. 根据“岗位标准映射”选择对应 Markdown 标准文件。
3. 读取对应 Markdown 标准全文，严格按标准做判断。
4. 用数据库岗位名或主要别名调用 `search_candidate_safe_profiles` 召回候选人。
5. 如候选人信息不足，用 `get_candidate_safe_detail_batch` 补充安全详情。
6. 逐个候选人对照 Markdown 标准，分为：
   - 推荐
   - 待确认
   - 不推荐
7. 推荐理由必须来自候选人的安全画像证据和 Markdown 标准要求。
8. 风险点必须明确，例如项目主导性不足、方向相关性不足、工作稳定性待确认、关键技能深度待确认。
9. 不输出联系方式字段。
10. 用户要求保存时，调用 `save_screening_result`。

## 推荐结果格式

推荐候选人时使用以下结构：

```json
{
  "task_id": "screen-YYYYMMDD-001",
  "standard_ref": "standard_markdown/yihai.md#CPU性能建模工程师",
  "recommended_candidates": [
    {
      "candidate_id": 123,
      "recommend_reason": "候选人的项目经历和技能证据如何匹配 Markdown 标准。",
      "risk_points": ["需要面试确认的风险点"]
    }
  ]
}
```

如果候选人安全画像中没有 `candidate_id`，使用后端返回的可识别 ID 字段；不要编造 ID。

## 人才库问答流程

1. 将用户自然语言问题拆成事实查询或候选人召回。
2. 统计类问题优先调用 `query_talent_pool_facts`。
3. 明细类问题调用 `search_candidate_safe_profiles` 或 `get_candidate_safe_detail_batch`。
4. 用自然语言组织答案，并标明回答基于当前安全数据返回结果。
5. 不输出超出字段权限的数据。

## 招聘数据分析流程

1. 明确分析对象，例如岗位、部门、候选状态、来源或时间范围。
2. 调用 `query_talent_pool_facts` 获取事实数据。
3. 必要时召回少量安全样本候选人作为证据。
4. 由 Agent 自己完成趋势、结构、缺口、风险和建议分析。
5. 区分“数据事实”和“Agent 推断”。

## 招聘报告生成流程

1. 先读取对应岗位 Markdown 标准。
2. 调用事实查询和候选人安全画像工具收集证据。
3. 由 Agent 生成报告，不调用后端报告生成能力。
4. 报告建议结构：
   - 目标岗位和标准来源
   - 数据范围和统计概览
   - 候选池结构
   - 推荐候选人及理由
   - 风险点和待确认问题
   - 下一步动作建议
5. 报告中不得包含联系方式。

## 受限岗位处理

如果用户要求筛选六类岗位之外的岗位：

- 不要直接套用现有标准。
- 可以调用 `query_talent_pool_facts` 回答事实性问题。
- 如果涉及推荐或筛选，应说明当前缺少对应 Markdown 标准，需要部门负责人补充标准后再做推荐。
